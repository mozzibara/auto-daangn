# 매물별 동·읍·면 허용 목록 — Cheonan / Asan

**중요:** 바로구매는 배송 옵션이며 지역 밖이라는 증거가 아니다.
매물이 검색 결과에 표시됐다는 사실 또한 개별 판매 지역의 증거가 아니다.
같은 동/읍/면이라도 직거래가 실제로 가능한지는 판매자에게 확인해야 한다.

## 설정 방법

저장소 `config/item_area_allowlist.json` 파일의 `allowed_areas`를 수정한다.
기본 허용 지역은 현재 연구에서 명시적으로 알고 있는 다음 두 지역뿐이다.

| 지역 | 설정 키 | 지역 ID |
| --- | --- | --- |
| 천안시 불당동 | `cheonan_buldang` | `2292` |
| 아산시 배방읍 | `asan_baebang` | `2333` |

이 ID는 현재 대상 지역 연구의 역사적 지역 ID이며, 최신 서비스 응답과의
일치를 별도로 재검증해야 한다. 위 두 지역 외에는 기본 허용하지 않는다.

다른 동·읍·면을 추가하는 예시 (아래 ID는 **미확인**이므로 null로 설정):

```json
{
  "key": "cheonan_dujeong",
  "city": "천안시",
  "district": "두정동",
  "region_id": null
}
```

`allowed_areas` 배열에 객체를 추가하면 된다. 유효한 지역명이 같은 시 안에서
중복될 수 있거나 구 경계 등으로 모호하다면 임의로 통과시키지 말고
정확한 first-party 지역 ID가 확인될 때까지 보류한다.

**절대로 `region_id`를 추측해서 기입하지 않는다.** 공식적으로
서비스가 반환한 동일한 매물의 지역 ID를 교차 검증한 경우에만 넣는다.
`region_id=null`이어도 본문과 무관한 구조화된 `city` + `name/district`
필드가 정확하게 일치하면 허용한다. 반대로 City 또는 Dong 이름만
존재하거나, 고정 ID와 모순되는 다른 ID가 반환되면 보류한다.

### 설정 파일 검증

```powershell
python -m scripts.check_item_area_config
python -m unittest tests.test_item_area_allowlist -v
python -m unittest discover -s tests -p 'test_*.py' -q
```

첫 명령은 **사이트에 접속하지 않는다**. 허용 범위는 해당 브랜치의
`main`에 포함된 JSON이 기준이다. 설정 변경은 리뷰·CI 후 병합한다.
초기 지역에 대한 기본 검색 조건/실험 통제 지역은 이 파일과 별도로
관리되며, 여기서 허용 지역을 늘렸다고 자동으로 더 많은 시·동을
검색하거나 기존 Asan 실험 통제군을 추천 후보로 승격하지 않는다.

## 판정 알고리즘

1. 기존 검색 자체의 `searchRegion.id`, `currentFilters.regionId`와
   실제 선택 UI 및 필터 영속성 검증이 통과해야 한다.
   현재 Issue #11의 `REGION_MISMATCH`는 여전히 미해결이다.
2. 먼저 실제 UI와 SHA로 연결된 **동일 Route 응답**에서
   `buySellArticles[*].region`만 사용한다. 원래 리스트와
   `href` 순서가 일치하지 않으면 파싱을 중지한다.
   `searchRegion/currentFilters`는 결코 매물 위치로 사용하지 않는다.
3. `region.id`가 설정에 고정된 ID와 일치하고 이름·시 정보에
   모순이 없거나, ID가 부재하고 구조화된 시 + 동·읍·면 이름이
   허용 범위와 정확히 일치하면 `ITEM_DISTRICT_ALLOWED`이다.
4. 구조화된 시 + 동·읍·면이 명확히 다른 지역인 경우
   `ITEM_DISTRICT_OUTSIDE_ALLOWLIST`로 분류한다.
   지역 ID의 단순 차이만으로 다른 지역임을 단정하지 않는다.
5. 불충분·모호·상충되는 필드, 손상된 JSON, 알 수 없는
   값은 `ITEM_DISTRICT_UNVERIFIED`로 판정해 **보류**한다.
6. 정확한 공개 상세 매물의 URL·가격 신원이 일치할 때만
   해당 지역 증거를 판매 가능 후보와 결합한다. 일반 매물과
   바로구매 매물에 동일하게 적용한다. 바로구매 자체를 제외하지 않는다.
7. 여러 관찰에서 동일한 매물의 허용 지역이 서로 다르면
   중복 병합 단계에서 격리한다. 불명확한 지역은 영구 삭제하지 않는다.
8. 검증된 매물의 정확한 시·동·읍·면은 소유자의 **암호화된
   비공개** v4.34 명단 및 로컬 비공개 Markdown에만 부가 표시한다.
   기존 v4.34 파일의 지역 정보 없는 레거시 항목도 계속 읽을 수 있다.
   OCI 검증 단계는 추가 필드까지 유효성 확인 후 DB 수집 여부를 판단한다.

## 개인정보·운영 경계

- 공개 아티팩트·일반 CI 로그에는 원문 주소, 판매자, 제목, 상세
  URL, 응답 JSON, 쿠키를 추가하지 않는다.
- 실제 매물 식별과 지역 이름을 연결한 표시 정보는 소유자 전용
  암호화 파일에만 포함된다.
- 지리 코드를 토대로 실거리, 동네 간 이동 시간, 실제 만남 가능 여부를
  추측하지 않는다. 시·동·읍·면은 행정구역의 이름이지 GPS 좌표가 아니다.
- 기존 최대 9건 상세 소스 + 6건 대조군 조사 범위 및 robots-first
  승인 정책을 변경하지 않는다.
- **지역 확정 오류를 우회하거나 OCI 자동 수집·백업을 활성화하지 않는다.**

## 미검증 항목

실제 현재 당근 Route의 매물별 `region.id` 및 `city` 구조와
메타데이터 충실도는 라이브 증거가 없으므로 아직 확정하지 않았다.
일부 지역명이 같은 시/구에 중복되는 경우 구 단위까지 확장한 별도
동명이동 충돌 방지 정책이 필요하다. 이 단계에서는 애매한 이름을
임의로 지역 확정하지 않는다.
